Work piles up. The Library is how you find your way back. Bookmarks for the things you return to, tags for the things that belong together, and a graph for how everything connects.

![The knowledge graph in the Library, drawing notes, files, events and people as connected nodes, with the type filters and Library sections in the sidebar](/docs/user/knowledge-graph.png)

## Bookmarks are yours alone

A bookmark is a private note to self. Nobody else sees your bookmarks. Not your manager, not an admin, not the owner of the thing you bookmarked.

You can bookmark anything you can open: a note, a file, a task, a project, an event, a channel, even a single chat message. The bookmark is a pointer, not a copy. Open it and you land on the live thing, exactly as current as it is for everyone else.

Because it is a pointer, it follows your access. Lose access to a note and its bookmark quietly drops out of your list. Get the access back and the bookmark returns. You never add it back yourself. If the thing itself was deleted, the bookmark says so instead of pretending it still exists.

Bookmarking changes nothing about the content. It grants no access, notifies nobody, and shows up in no one's activity.

## Tags are a shared vocabulary

Tags work the other way around. There is one set of tags for your whole organization, and a tag spans every kind of content. Tag a note, a file, and a project with `onboarding` and they now belong together, even though they live in three different places.

Adding or removing a tag counts as editing, so you need edit rights on the thing you are tagging. Reading is looser: anyone who can open the content sees its tags. One item holds up to 20 tags you add by hand.

A tag page shows only what you can open. Two colleagues click the same tag and get different lists, each one honest about their own access. A tag that sits entirely on content you cannot see does not appear for you at all. So tag freely: the tag never leaks the content it is on.

Tags also work in search. Filter any search to a tag and the same rule holds: you only get results you could open anyway.

## The graph draws what you meant

Every time you mention something in Uniffy, you are stating a connection. This task came out of that meeting. This note explains that file. The knowledge graph takes those mentions from your notes, tasks and calendar events and draws them as a living map.

Nobody maintains this map. It exists because the mentions exist, and it updates when they change. Delete the mention and the line goes away.

It is your map, not the organization's. The graph shows only content you can open, so your graph and a colleague's graph of the same team are different pictures. There is no master graph an admin can pull up to see everything.

Click a thing and the graph narrows to its neighborhood. When you are inside a note and want to see its place in the whole, use Show in graph and you arrive already centered on it.

The graph is honest by construction. If a line is there, you can open both ends. Which makes it a good place to start on your first week: open the graph, find the busiest node, and read outward from there. That node is what your team actually talks about.
